 ●   Components: The building blocks of a React application. Components are reusable, independent, and can be either

 ●   Props: Read-only data passed from parent components to child components, allowing for dynamic and customizable
     content
 ●   State: An internal data store within a component. When the state changes, the component re-renders to reﬂect the
     updates.
 ●   Unidirectional data ﬂow: Data in React ﬂows in a single direction, from parent to child components, ensuring
     predictable and maintainable state management.
 ●   Virtual DOM: A lightweight copy of the actual DOM that React uses to eﬃciently update the UI. It minimizes direct
     manipulations of the real DOM, improving performance.
 ●   Hooks: Built-in functions that allow functional components to use state and other React features without needing class components.
     Examples include useState and useEffect.
 ●   React Router: A library that enables navigation and routing in React applications, allowing users to move between
     different views or pages without full-page reloads.

Redux
• Redux is a state container for JavaScript apps,
  often called a Redux store. It stores the whole
  state of the app in an immutable object tree.
• Actions: Actions are how the application interacts
  with the store. The application sends an action
  with some attached data. These actions are then
  handled by a so-called reducer.
• Store: This structure stores the complete state of
  our application. Given only the content of the
  store, the application should be able to save and
  recover the current state of the application
• Reducer: The Reducer is a function that takes the
  current state and an action and transforms it to a
  new state.
  Redux
• The state is read-only: The state of the application can only be changed via
  actions. This is very useful for debugging since the changing state flow is
  much more clear.
• The Redux store API is tiny and has only four methods:
   • store.getState()—Returns the current state object tree.
   • store.dispatch(action) - Dispatch an action to change the state.
   • store.subscribe(listener) - Listen to changes in the state tree.
   • store.replaceReducer(nextReducer) - Replaces the current reducer with another.
     This method is used in advanced use cases such as code splitting

Prompt Engineering
    Prompt Engineering— Deﬁnition
Prompt engineering is the practice of designing the input text (and optional
parameters) that steer an LLM’s behavior toward a specific goal. It focuses on what
you provide the model: clear task framing, constraints, desired style, output format,
and any evaluation cues.

Prompt formula:
Task + Constraints + Output Format (+ Hints / Examples)

Why it matters:

●    Improves output quality and reliability.
●    Supports evaluation and safety (e.g., grounding, refusals, format control).
●    Is inherently iterative—effective prompts usually require testing and refinement.

A 5-prompt method to build a grounded kit
Build the system in stages: define the job, ground it, design the process, add controls, package it.


  1    Frame the task: what the AI is supposed to do
       Purpose, boundaries, required inputs, desired output, and when a human must review.

  2    Add grounded context: what sources the AI is allowed to use
       Use only approved sources; state freshness & citation; mark missing info; don’t invent.

  3    Design the workflow: turn the task into a process.
       Map intake → approved use; per step: owner, input, action, output, escalation path.

  4    Define controls & evaluation: How to evaluate the AI is behaving correctly?
       Privacy rules, human-review triggers, a 1–5 scorecard, a release rule, and test cases.

  5    Assemble the kit: build the actual reusable package
       Production prompt, intake form, output format, checklists, test set —
       participant-ready.

Deﬁnition: combine a parametric model with a
non-parametric memory (retriever + index) so outputs can

(2) Retrieval + generation (fetch top-k, then prompt an LLM).

Why it helps: improves speciﬁcity and factuality vs.
parametric-only models.

    ○   Provides abstractions for prompts, tools, agents, memory, and
        workflows.
    ○   Lets you combine LLMs with other software systems (search engines, APIs,

RAG Quality Levers (retrieval side)
• Embeddings model: pick for domain/language; better sentence
  encoders improve top-k recall and margins (dimensionality ≠ quality).
• Chunking strategy: sentence/recursive for coherence; token for strict
  budget;
• semantic for content-aware splits; hierarchies for multi-scale retrieval.
• Retriever settings: k, metric (cosine/dot/L2), MMR/diversity, and
  optional
• rerankers (cross-encoders) for higher precision.
LangChain: simple RAG with LCEL
 Minimal pattern
 from langchain_openai import ChatOpenAI, OpenAIEmbeddings
 from langchain_community.vectorstores import FAISS
 from langchain_core.prompts import ChatPromptTemplate
 from langchain_core.runnables import RunnablePassthrough

 # 1) Build/store the index (offline)
 db = FAISS.from_texts(docs, embedding=OpenAIEmbeddings())
 retriever = db.as_retriever(search_kwargs={"k": 6})

 # 2) Compose a RAG chain (online)
 prompt = ChatPromptTemplate.from_messages([
    ("system", "Answer using ONLY the context. Cite sources as [#]."),
    ("user", "Context:\n{context}\n\nQuestion: {question}")
 ])
 llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

 rag = {"context": retriever, "question": RunnablePassthrough()} | prompt | llm
 rag.invoke("What is top_p?")
LlamaIndex: query engine with citations
 Typical pattern
 from llama_index.core import VectorStoreIndex, SimpleDirectoryReader
 from llama_index.core.node_parser import SentenceSplitter

 docs = SimpleDirectoryReader("data/notes").load_data()
 nodes = SentenceSplitter(chunk_size=512,
 chunk_overlap=80).get_nodes_from_documents(docs)

 index = VectorStoreIndex(nodes)
 query_engine = index.as_query_engine(similarity_top_k=6)

 response = query_engine.query("Explain temperature vs top_p.")
 print(response.response)
 print(response.get_formatted_sources())
